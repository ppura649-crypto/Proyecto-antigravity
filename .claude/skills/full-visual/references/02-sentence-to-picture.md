# Which picture for which sentence

## Goal

For every sentence, the one real thing it is about, doing the one thing the sentence says, changing on the word that
says it. Written down as a plan the creator approves in words before any pixel exists.

## Reasoning

A viewer believes what they can see happen. "Your signup form has no age question" is a claim; a signup form filling
itself in, then a red dashed row opening where the age question should be, is evidence. The references never show a
chart, a stock icon or an abstract shape where a real artefact exists: they show the form, the judgment, the terminal,
the invoice, the profile. And they redraw it rather than record it, because only a drawn interface can turn red on a
word, grow a row, or become 108 copies of itself.

Fidelity goes to the maximum, scope to the minimum: real geometry, real copy (a correct `curl`, the real statute
number, the verbatim licence), and only the rows the sentence needs. A real screenshot is nine tenths irrelevant pixels
and one tenth illegible ones.

Start from the script, not from a look: for each sentence, name the real-world thing it is about, its verb, and who
does it to whom. A sentence with no thing (a pure link, "it's a free skill called") gets nothing new: the stage keeps
living. Those are the weakest beats of any reel, so rewrite the sentence if you can.

## The table

| The sentence... | The stage shows |
|---|---|
| names the viewer's own thing ("your signup form") | that interface, clean, filling itself in live |
| names a fault, or something missing | the same interface breaking in place. Absence cannot be drawn, its correction can: an inserted red dashed row with a `missing` pill, or a find bar typing the clause and returning `0 of 0` |
| states a price or a number | a counter that runs and lands on the word, at hero size when it is the payoff, with one grey line citing the source |
| multiplies ("per visitor", "5,000 were filed") | the single thing becoming a field of copies from its own position, while a counter runs |
| crosses a limit | a gauge or a bar filling, and flipping colour on the frame the value crosses, not on a word |
| names a repo or a tool | its GitHub card, the name typing on, the stars counting |
| describes a process between two parties | one artefact physically travelling between two identical panels; role badges and a round counter carry the state |
| says "turns X into Y" | X becoming Y on screen |
| claims a default, a setting, autonomy | a switch the cursor flips, and the consequence visible at once |
| cites authority | the real document, or a portrait with a name and a job title |
| lists stages in one sentence | columns or rows lighting in order, one per word |
| names the villain, or negates | one object alone, struck through in the reel's only red stroke |
| turns the argument | a physical object (a stamp, a calendar rewinding) or the one layout move of the reel (two cards swapping, the ground turning white) |
| gives the instruction | the action performed by a cursor in the real interface, then its reward: the DM arriving, the invoice zeroed, the count ticking +1 |

## Two habits above the table

**One continuous thing per reel.** An invoice that gains a line per item; the same nine objects flowing through five
layouts; two identical cards plus a terminal; one grid read four times (flags, then rates, then a scan, then marks).
Name it in the plan. It is what makes six items one film instead of six slides, and it doubles as a progress bar.

**A change of state never brings a new object.** The limit bar turns into the fallback bar turns into the token bar:
one rectangle, three states. Locks open, a gauge turns red, a row is inserted, a card desaturates. When something new
must arrive, the old thing is dimmed, shrunk and moved, overlaid, or morphed into it. Nothing is pushed sideways, and
the slot for a late arrival is left empty from the start.

## plan.md

Per sentence: the words; the real thing and its source (the URL, the document, the product screen it is redrawn from);
the verb; what is already on screen from the previous sentence; each event as `word → what changes`, marked "lands on"
for a single event or "ends on" for a build; what it hands to the next sentence. Then, once for the reel: the
continuous thing, the pinned chrome, the grounds, the one turn. The creator reads this in words and approves it, or not.

### What good looks like

- Reading only the right-hand column of the plan, someone could retell the script.
- Every item uses the same skeleton, and the last item breaks it on purpose.
- The densest stage has at most five to seven things, each in a slot that was reserved for it.
- The payoff number is the only thing allowed to be bigger than the caption, and everything above it dims when it lands.
- People are portraits or drawn faces with a name, never initials or grey placeholders. Real logos only, fetched, never
  constructed.
- The first frame is the first word alone with the first object mid-entrance. The last frame reads on its own if paused.

### Traps

- A metaphor where an artefact exists (a shield for "security", a rocket for "launch").
- A whole perfect interface where one row carries the sentence.
- A new card per sentence. Ask first what the thing already on screen can do.
- Evidence set in type nobody can read: below 32 px it is texture. Fewer rows, bigger.
- A list with no structure mark: the viewer cannot tell how much is left. Give it the continuous thing, or the pill.
- Copying a claim from a reference reel into a plan. Verify it or drop it.
