# Learn the decisions, not the pictures

These examples describe transferable editing logic. They are neither buyer preferences nor source
evidence for a new video's factual claims. Change the objects, layout, timings and presentation
to fit the recorded argument. Select the cases relevant to the current passage.

Unless labeled source evidence, a sequence below is an illustrative adaptation. Research ranks,
video codes and times identify where a decision was observed; the pack needs no research folder
or reference video to use the reasoning. They do not establish creator intent or prove a tool's
claims. Follow the buyer's preferences when applying the logic.

## Two contributors, one working surface

**Goal.** Understand how two tools contribute in the same environment.

**Sequence.** Establish both actors above a shared terminal. Move attention to the first actor's
colored contribution. Pan within that same terminal to the second actor's contribution. Return
wide so both contributions can be seen together.

**Why.** The shared object supplies continuity, color supplies ownership, and the final wide state
resolves the relationship. A pair of unrelated close-ups would require the viewer to infer the
connection. Two logos sliding in would name participants without explaining their collaboration.

**Adaptation.** The same reasoning can explain an editor and reviewer, two stages in a workflow,
or a handoff between people. Use the actual work product and a consistent anchor. Full visual
is useful when the relationship needs the canvas; a compact version can remain split.

## A limit causes a handoff

**Goal.** Understand what triggers an automatic switch and what happens afterwards.

**Sequence.** Productive work progresses while a finite meter drains. The number, bar and warning
color agree. At zero, output visibly stops. Alternatives move through a fixed selection position.
One settles, the status changes to successful, then the presenter explains continued work.

**Why.** Trigger, failure, selection and result form a causal chain. The fixed selection target
lets moving candidates remain readable. The completed state matters more than a perpetual loop.

**Counterexample.** A red error replaced by a green tick implies recovery but omits how it occurs.
Do not copy an illustrative carousel's candidate order as a real routing algorithm. Distinguish
the application that remains open from a model or provider that changes behind it.

## A file makes an aesthetic usable

**Goal.** Understand how a visual reference becomes instructions an agent can apply.

**Sequence.** Establish a desirable reference. Show its actual design file beside it. Blur or
de-emphasize the image while enlarging the readable file and relevant controls. Show colors,
type, spacing and rules in their own native forms, then a corresponding result.

**Why.** The file is the missing intermediary between aspiration and execution. Selective focus
changes the hierarchy inside an established surface instead of discarding it for a new card.
The categories can remain split when recognition, rather than reading every value, is the job.

**Counterexample.** A famous logo followed by a polished but unrelated page hides the mechanism.
Recoloring the real interface into the creator's palette also sacrifices recognition for style.

## Follow the diagnosis inside one interface

**When and goal.** A claim concerns catching an error. Help the viewer connect the apparently
working page, its hidden failure and the diagnosis, rather than merely recognize the app.

**Source evidence.** Rank 25, `DbyJNRdPyCj`, 9.800 to 12.067 seconds: the whole checkout workspace
is visible at 10.000, the runtime-error region is enlarged at 10.800, and the crop moves across
to the assistant's highlighted diagnosis by 12.000. The surrounding interface remains recognizable.

**Why this choice.** The interface already contains the argument. Moving attention between its
related regions supplies context, symptom and interpretation without making the viewer rebuild
a mental map. Full visual gives the small diagnostic text room; the presenter would compete
with the reading task here.

**Illustrative adaptation.** Establish the user's actual failing screen. Keep one source window
and stable landmarks. On the relevant spoken anchor, move toward the observable failure, settle
long enough to read it, then move to the diagnosis. Return wide only if the repaired state needs
comparison. Choose crop and duration from the current source, not these research timestamps.

**Counterexample.** Zooming repeatedly toward arbitrary controls adds energy but no explanation.
An assistant saying it found the problem is evidence of a diagnosis, not a demonstrated repair
or proof that the advertised tool produced it. Show the working result if the sentence claims one.

## Keep the previous step while introducing the next

**When and goal.** A short access procedure has several dependent steps. Let the viewer retain
the path to the outcome while learning each new action.

**Source evidence.** Rank 26, `Dbvkxq3SAE0`, 23.500 to 28.133 seconds: three numbered interface
cards accumulate downward. At 24.700 the first is labeled while the second enters; by 26.600
the destination, signup and creation steps are all present. The completed stack then holds.

**Why this choice.** Earlier steps become persistent context. The full canvas supports the
relationship among steps, while a succession of replacements would require the viewer to
remember a disappearing instruction. Once assembled, the layout stops demanding a new search.

**Illustrative adaptation.** Show the actual destination first, reveal the next action on its
spoken cue, and retain completed steps at readable size. Give the current action the strongest
contrast. Finish with all steps and the usable destination visible. If controls become too small,
show the active interface large with a compact persistent progress list instead of shrinking
everything to preserve a three-card picture.

**Counterexample.** The reference labels its middle card as signup but shows an offer page,
not the signup form. Copy the cumulative teaching logic, then supply the correct control and
current terms. This arrangement explains a path; it does not prove a completed transaction.

## Show the result, then earn the mechanism

**When and goal.** A build process is complex enough that its logs have little meaning before
the viewer knows what they produce. Give the viewer a reason to inspect the process.

**Source evidence.** Rank 15, `Dcbbs44vQCO`, 24.000 to 26.800 seconds: a finished orbital drone
appears above the presenter first. At 24.467 the same upper frame switches to a build dashboard
with a bare stand. Parts accumulate alongside advancing build steps until the object develops.
The lower presenter stays in place across this result-first, process-second change.

**Why this choice.** The recognizable output gives the logs a purpose. Keeping the viewing
window stable makes the reset interpretable as a closer explanation of the same task, rather
than an unrelated example. Split works because the object is readable at that size.

**Illustrative adaptation.** Briefly show the real outcome, establish the earlier input state,
then connect each meaningful operation to a visible change in that same result. Label a staged
reconstruction as an illustration; distinguish a source example from the buyer's own tool run.

**Counterexample.** Rank 27, `Dbn6ElTvw_W`, 48.233 to 52.133 seconds shows queued tasks becoming
completed beside an observing mascot. That depicts observation and progress, but the spoken
learning claim has no changed preference or skill on screen. To explain learning, show an actual
correction, the resulting instruction change, and a later output that applies it. If that evidence
is unavailable, present the proposed mechanism honestly instead of treating a plausible animation
as demonstrated behavior.

## A message loses visibility

**Goal.** Perceive why an outgoing message becomes difficult to notice.

**Sequence.** Establish the identified message inside a recognizable inbox. New rows enter above
it, moving all existing rows down together without changing their ordering. The target moves
out of the initial attention area. Hold the final state before the speaker interprets it.

**Why.** The viewer tracks an actual change in position and salience. The object's identity,
row geometry, timing of arrivals and final location carry the explanation.

**Counterexample.** Floating envelope icons communicate quantity but not burial. A static inbox
communicates category but not the change. A shake adds urgency without explaining anything.

**Builder detail.** Specify the inbox chrome, sender/subject hierarchy, target identity, row
spacing, arrival ordering, spoken anchors and crop. Use authorized actual content or clearly
fictional demonstration data. Decide whether the tracking remains readable above the presenter.

## One map, several alternatives

**Goal.** Understand an ordered check of existing solutions before writing new work.

**Sequence.** Establish three fixed source locations and their connecting branches. Draw and
brighten one route on its spoken category, keep other routes dim, then transfer attention to
the next without moving the whole diagram. Finish on the final named location.

**Why.** The stable map makes enumeration cumulative and comparable. This is a valid role for
simplified symbols: the relationship is the subject. It does not make generic icons a good
replacement for a particular interface the viewer must recognize.

**Counterexample.** Replacing the whole diagram with each new noun removes the shared structure.

## Subtraction makes reduction visible

**Goal.** Perceive a measured reduction without reading every line of a document or code file.

**Sequence.** Keep one window fixed. Mark the parts that change, remove them progressively,
and update the relevant counter. Let the growing empty space reveal the reduction. Hold the
shorter result with its measurement once the operation is complete.

**Why.** The container is a stable comparison reference and the changed property is animated
directly. A final screenshot alone does not supply a before-state.

**Counterexample.** Removing validation to make code shorter may change behavior. Use an equivalent
tested example when equivalence is claimed. A green check is not evidence that a test passed.

## The person can be the right image

A prerequisite, reassurance, interpretation or coherent use-case list can stay on the presenter
without a new graphic. Some face beats punctuate the end of a clause in less than a second;
others need several seconds. A completed demo can return to the person before introducing the
next question. Do not fill this space solely because the tool can draw something there.

The final invitation usually benefits from simpler attention and a held action phrase. Preserve
the creator's actual resource and delivery method instead of copying a reference keyword.
