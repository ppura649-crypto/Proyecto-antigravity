# Start

## Goal

After this runs, the folder knows the person well enough that no format has to ask a question the account or the buyer already answered. The buyer reaches Home immediately; shared context grows from their account and any remaining answers.

## Reasoning

Start learns who the person is, what they post and how they write. The last 90 days of captions, bio and up to 12 recent thumbnails are enough for that first context. No video downloads, frame scans, motion analysis, sound fingerprints or on-screen OCR belong in onboarding. A creator who only owns Talking Head must never wait for a Trial Reels study. Ask only what the account cannot answer, following `references/questions.md`.

## Pattern

If every installed pack declares `needs.account: false` in `runtime.json`, run machine setup, share Home and continue into the requested format. Do not open account setup or request an account key. Product Demo starts from the product brief. A mixed folder can keep its account reading separate from the product film.

1. Check Node from the shell and install it yourself if missing. Run `node scripts/workspace.mjs --ensure --no-open` and share Home immediately. Read `context/onboarding.json` for saved entry details and `context/start.json` for account context. The welcome is dismissed permanently by Go to Home or Do this later; never clear its completion or send a returning buyer to `/onboarding`. If account context is done, update only the chosen section. Account connection, reading, questions and review are background account work, never a gate into Home or format setup. Never reset a format setup when account setup runs.
2. Run `node scripts/doctor.mjs`. It checks packages, ffmpeg, disk, keys and the account connection. Run every fix marked `who: "agent"` yourself. On Windows or Linux a fix can fail because this folder was built on a Mac: make it work on this machine, changing only the means and never the feature, the end goal or the quality, and note it in `context/machine.md` as AGENTS.md says. Ask only for passwords, permissions or an application restart the agent cannot perform. A missing account connection blocks account reading, not footage-led work. Do not render past a failed rendering prerequisite.
3. If the key is missing, run `node scripts/keys/server.mjs` and point to the page. Follow `references/access.md` for the buyer's own workspace and project. Leave the account task pending while the buyer works in their formats. Never accept a key in chat.
4. Reuse the platform and handle from the prompt or `context/onboarding.json`; do not ask again. For Instagram, run `node scripts/profile.mjs --handle <their-handle-or-link>` as background account work. The saved Instagram handle or profile also works without the flag. The script verifies the connected identity, saves the name and local avatar before reading posts, and keeps initials if the picture is unavailable. It opens any required account approval; Instagram needs a Business or Creator account. YouTube and TikTok readers are not shipped: retain that requested account for later and keep formats available, never pass it to the Instagram reader. A connection issue affects only this account task. See `references/access.md`.
5. `profile.mjs` defaults to 90 days. It saves captions and metadata, plus at most 12 thumbnails, without requesting insights per post or downloading videos. Run `node scripts/context.mjs`: its default account scope measures captions only. `context/account-scope.json` identifies the recent posts and previews; older saved posts are not onboarding inputs. Never run detailed readers to finish start.
6. **Ask only what remains unknown while it reads.** Read `references/questions.md` against the captions and bio already saved. Write `context/answers.json` with each fact marked as account or buyer supplied. Write `context/questions.json` as `{ questions: [{ id, ask, options?: [string] }], readback: [string] }`, with at most three unresolved questions and no questions the account answers. Share `/setup/questions`; the buyer answers on the page and copies the prompt into chat. The agent saves those answers, removes answered questions and rewrites the readback. A page draft is never a saved answer. With nothing to ask, write an empty questions array and continue the reading.
7. Read the recent captions, the bio and those thumbnails. Write `context/profile.md` (who they are, their audience, topics and posting habits) and `context/voice.md` (their caption pattern from `captions.json`, with examples). Save inferred language in `profile.json` and the shared facts with provenance in `answers.json`; see `references/context.md` for the data handoff. Preserve buyer edits and unknown values. Thumbnails cannot establish speech, cuts or performance. Detailed `formats.md` and `text-system.md` belong to Trial Reels. Put remaining questions and five brief readback lines on Home for later review.
8. Write the five brief readback lines into `context/questions.json` and share `/setup/readback`. Read the current account notes, including direct buyer edits. Apply corrections from the buyer's copied chat prompt to the source answers and affected notes, preserving saved edits, then rewrite the readback. Write `context/start.json` with done, date, setup version and profile hash only after the reading is complete, no questions remain and the buyer confirms the readback in chat. The page never marks setup done. Home picks up the saved state without a reload. Generate `board.html` only when a static copy is needed.
9. After the readback is confirmed, inspect `runtime.json`. **If Trial Reels is installed, continue straight into its skill in the same conversation** and run `node scripts/trial-reels/analyze.mjs`. No second command or format choice is needed. This is a separate six-month, top-50 read with its own progress. If it is not installed, do no Trial Reels work; follow `node scripts/next.mjs` for the formats the buyer owns. Never claim a task is running without its progress record.

## Examples

A buyer whose last twenty captions mostly open with "Comment WORD and I'll send you": automation is yes, the DM carries what those lines promise, nothing is asked. A buyer with nine posts and no captions: three questions, automation, who it is for, what they are credible for, and the voice file is marked thin until there are captions to measure; `captions.json` reports `posts_read` so thin is a number and not a feeling.

## Counter-examples

Asking anything the account already answers. Asking which automation tool it is: nothing we make changes with it. Asking "do you want music" (a format decides). Asking what the goal is, where the footage lives or how many posts a week: nothing we produce changes with the answer. Ending start with a list of things the buyer could say next, when one format is installed and its command is the answer. Making a buyer with one format choose. Writing profile.md from the bio alone instead of the recent captions and thumbnails. Writing voice.md from reading a few captions instead of from `captions.json`, which measured every one of them. Scanning six months of video to learn who the buyer is. Blocking Talking Head on detailed format research. Continuing past a missing key by typing it into a file for the buyer.

Read `references/context.md` for the files and the gates every format checks, and `references/access.md` for the exact steps that give the folder access to the account.
