# Context files and gates

`scripts/readers.json` says what every reading is made of and `scripts/context.mjs` is the only thing that runs them: it works out what is missing or older than what it came from, runs those in dependency order with the independent ones at the same time, and `--check` says what is behind without running anything. Never call a reader by hand. Every reader writes a `.json` of what it measured, for the scripts and the checks that compare against it. Every thing that has to be understood before something is written gets a `.md` next to it, written high perspective by the agent: the goal, the reasoning, the pattern with its numbers inside sentences, examples and counter-examples. A script never reads the markdown and nobody writes from the JSON.

## Files

- `context/onboarding.json`: `{ version: 1, done, at, stage, platform, handle }`. The workspace saves the selected account and permanently sets `done` on Go to Home or Do this later. This is entry completion, never evidence of account access or finished learning. Reuse its handle before asking; the optional Composio key is stored only in `.env.local`. Existing accounts and format work bypass the welcome. Account refreshes, remaining questions, format additions and setup version changes never reset this file.
- `context/profile.json`: normalized handle, account id, display name, platform, followers, bio, link, account type, language, cadence per week, connected toolkits, identity_at and pulled_at. Identity is saved before posts. `avatar` is `{ path, status, checked_at }`; the reader downloads the connected creator's photo into `context/profile/avatar-<content-hash>.<png|jpg|webp>`. The workspace serves this local image in the sidebar and Account page, and never exposes its temporary provider URL. Failed photo downloads retain a cached picture or initials and do not fail account reading.
- `context/posts.json`: saved posts with numbers, captions and download links. Onboarding uses only the last 90 days from `account-scope.json`, with up to 12 thumbnails and no video downloads. Trial Reels separately adds six-month metadata and selects its best 50 in `context/trial-reels/selection.json`. Refreshed when the buyer says refresh (`scripts/refresh.mjs`, which pulls and then runs the readings, so it never leaves a post nothing has read). `hooks/session-start.mjs` says in one line when the reading is behind and pulls nothing on its own.
- `context/answers.json`: the facts every format reads, written from the account and corrected by the buyer. Shape: `{ funnel: { dm_automation: { enabled, live_on_reels }, deliverable, destination }, audience: { for, need, not_for }, credibility: [], voice: { never: [], always: [], reference_posts: [] }, footage: { drive }, read: { <field>: "account" | "buyer" } }`. `read` says where each fact came from. `footage.drive` is set by a format's setup when Drive is connected, never by a start question.
- `context/structure/<id>.json` and `.jpg`: the structure reading of a selected format reference or source video, written by `scripts/structure.mjs`: layout, split, cuts and motion per half (one shot, a timelapse, cuts), the flow numbers that identify a reused take, text position, a contact sheet.
- `context/sounds.json` and `context/sounds/<id>.m4a`: written by `scripts/sounds.mjs`. Which posts share a track (fingerprinted locally, never sent anywhere), the track copied out of the longest post that carries it, its reach; which posts sit on a library sound, which Instagram keeps out of the API along with the file.
- `context/formats.json`: written by `scripts/formats.mjs`. The posts grouped into formats by their zones, each with its count, reach, split range, the takes reused (by flow signature), the sounds and the sheets of its top posts. The agent names the formats in `context/formats.md`.
- `context/profile.md`: the prose the agent reads first. Rebuilt whenever one of the files above changes.
- `context/formats.md`: the account's formats as structures with slots, each with its posts, its numbers, example cards, and the material that makes it again. Every format skill reads it before its shortlist.
- `context/text-system.json`: written by `scripts/textsystem.mjs`. How a line is built per format, measured: rows, characters a row with the ninetieth percentile, case, shapes and the reach of each, the top lines. The checks read this file, `checks/textbudget.mjs` compares every new line against it, and it is never deleted.
- `context/text-system.md`: the same reading, understood and written down by the agent, shape in `references/text-system.md`. This is what anyone writing words for the screen reads, in any format. Rebuilt whenever the reading is.
- `context/voice.md`: the voice as measured, with five or six captions in full and the word lists.
- `context/start.json`: `{ done, at, version, profile_hash }`.
- Shared topic direction lives in `context/answers.json` under `audience.for` and `audience.need`, with provenance in `read`, and is understood in `profile.md`. A format may fill a missing fact without rerunning account setup. Every format reuses it. No format keeps a separate copy of these answers in its setup file.
- `context/questions.json`: `{ questions: [{ id, ask, options?: [string] }], readback: [string] }`. Only unresolved account questions, at most three, and five brief readback lines. Written by the agent, read by `/setup/questions` and `/setup/readback`. The buyer copies answers or corrections into chat; the agent updates `answers.json`, removes answered questions and rewrites the readback before confirming setup. Browser drafts never change this file or `start.json`.
- `workspace/library/<format>.json`: the one file a format keeps. `{ setup: { done, at, version, example }, answers: {}, stages: [the ladder], stage: { n, of, id, name, next, say, round }, plan: { what is done, what is needed, what to run now }, formats: { <id>: { rules, first } } }`. The setup block is the internal setup skill's; the rest is the format's `plan.mjs`. Nothing else writes it, and the plan is never written anywhere else: the board and the handoff both read this file, and two copies of one answer is how a folder starts disagreeing with itself about where the buyer is.

## Gates, in order, before any format does anything

These checks describe the data a production step uses. None is a route guard for Home or an installed format's setup. Keep the account worker running independently of browser navigation.

1. `context/start.json` missing or not done: Trial Reels waits for start. Talking Head can use its clip and words; Quick Cuts can use footage and saved defaults while the account reads. A topic-led reel without account notes needs the buyer's explicit topic and audience in its project brief. Never invent account knowledge or mark start done to bypass this gate.
2. `workspace/library/<format>.json` missing or setup not done: run the format's setup, then continue.
3. Setup version below the format's version in `setup.json` (falling back to the pack version): ask the new questions only, except Talking Head. An explicitly saved Talking Head look is reused even with an older version; only Edit look or an explicit setup request changes it. A new clip can still need footage or a transcript.
4. `node scripts/context.mjs --check` checks the cheap account scope only. Trial Reels uses `analyze.mjs --format <id>` or `--post <id>` for its bounded references. Missing format or text-system readings never block account onboarding or Talking Head. Refresh only the scope the current work uses. A version checked against a text budget from before the last twenty posts passes its checks and is wrong, and no check can catch that, because every check compares against the stale reading itself.
5. Profile refreshed and changed a lot since setup (a new top format, followers doubled, a new bio link): say so in one line and offer an update. Never force it.
6. Otherwise run without a question.

## Re-run

`/start` with existing context says what it knows in five lines and asks what to update: account, answers, voice, footage, library. Only that section runs again.

## Data handoff before marking the account read complete

Check `profile.json`, `posts.json`, `account-scope.json` and `captions.json`, then the human reading in `profile.md` and `voice.md`. Empty posts or an unavailable photo are valid recorded outcomes, not invented evidence. Only the authenticated account supplies identity; a typed handle must match before its posts are read. Names and pictures never come from unrelated account searches.

The script measures cadence and caption patterns. The agent infers language from the captions, preserves an already confirmed language, and saves it in `profile.json`; multilingual or insufficient evidence may remain uncertain. The agent writes shared audience, audience need, credibility, voice constraints and delivery context to `answers.json` with `read` provenance, then explains those facts in the Markdown. Keep inferred CTA habits distinct from verified automation access and audience demographics. Unresolved facts can stay as Home questions or be supplied by a topic format later.

The first read does not request per-post insights. Likes and comments may be present; reach, views, saves, shares and watch time remain unknown unless a separate requested insights reading or Trial Reels saved them. Never turn missing metrics into zero or call engagement evidence reach. Format look, footage, transcripts, song choices, research and project progress stay in their format's own setup and runs.
